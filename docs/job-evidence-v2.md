# 求职展示：实现、证据与讲解边界

定位：校招 AI Agent 应用开发项目。演示使用 DeepSeek 显式配置；Qwen 保留
本地 vLLM 部署与独立评测记录。所有金额变化都是模拟业务，不接真实支付。

## 三个值得展开讲的设计

### 模型负责调查，程序负责业务约束

问题：用户可能描述不完整，也可能要求退整单、任意金额或跳过审核。
模型通过 MCP 查订单、物流和售后历史，通过 BGE/pgvector 查政策，再提交方案。
金额由业务数据计算，资格由版本化规则判断，审核和执行由服务端会话及独立执行器控制。

可展示：多商品订单只退故障商品；用户说“直接退款”仍需审核及确认。
源码入口：`commerceflow/agent.py`、`tools.py`、`policy.py`、`cases.py`。
追问准备：为什么不能仅靠提示词防越权？为什么政策检索不能代替资格判断？
答题依据：提示词可能失效；检索相似不代表满足时间、金额和重复权益约束。

### 授权绑定方案版本，业务写入可恢复

问题：批准耳机退款后改成鼠标，或者业务成功但网络响应丢失，直接重试可能造成误操作。
方案版本不可变，审批绑定哈希；新消息使未执行旧方案失效。确认和任务同事务落库。
worker 按原执行ID核验；commerce 在同一事务中校验权益、更新商品余额、写工单和幂等结果。

可展示：换目标后旧批准不能执行；响应丢失与进程终止后仍只有一条退款结果。
源码入口：`cases.py`、`worker.py`、`commerce.py`、`tests_v2/test_recovery.py`。
追问准备：请求幂等键与权益唯一键有什么不同？为什么业务锁不能只放在 Agent 侧？
答题依据：前者防同一请求重复，后者防不同案件重复申请同一权益；最终业务服务必须独立防重。
不要宣称通用分布式 exactly-once；本项目是在明确事务与唯一约束范围内保证业务效果不重复。

### 用评测区分安全、效果和成本

问题：演示成功不代表模型稳定，安全拦截也不代表用户任务完成。
同时保留固定工作流、Qwen、DeepSeek 的原始结果与失败。模型调用共享持久化预算账本，
请求前原子预留、返回后结算，未知用量保留预留。

可展示：[改进实验](../eval/reports/v2/IMPROVEMENT.md)、
[原始Qwen报告](../eval/reports/v2/REPORT.md)、
[恢复凭证](../eval/reports/v2/recovery-proof.json)。
追问准备：为什么固定流程仍有价值？改进后为何不能称为未见测试集成绩？
答题依据：明确业务规则适合确定性执行；Agent 的价值在自然语言调查与多轮补充。
看过测试失败后做的修改属于回归改进，需如实报告；多次运行不是新增独立样本。

## 三分钟现场顺序

1. 选择未使用权益的订单，说明只有一个商品有质量问题。
2. 展示模型的真实工具调用与政策依据，核对剩余实付金额。
3. 在独立审核员会话批准，再由客服确认执行；展示业务凭证。
4. 用补偿重复申请或换商品后旧审批失效说明业务边界。
5. 打开评测报告，说出模型、分子分母、主要失败和费用；恢复实验展示其真实记录。

现场不能重复使用已消费权益的订单来追求“每次都成功”，也不要删除历史凭证。
选择新订单或新建独立演示库；不要清空预算账本。

## 可以写与不能写的主张

- 可以：实现真实工具调用、版本化审批、受控执行、持久化任务和真实进程恢复验证。
- 可以：引用报告中的完整集成绩，并同时标注模型、合成数据规模及回归口径。
- 不能：自研/微调大模型、生产级真实支付、企业大规模知识库或真实客户业务收益。
- 不能：把两条政策的100%召回说成大型RAG系统效果；把API费用上界说成供应商账单。
- 不能：把Qwen原始成绩替换成DeepSeek成绩，或隐去表现更好的固定工作流。

项目由 AI 辅助开发。面试时个人贡献应以自己能说明和复现的部分为准；至少独立走通
“用户消息 → MCP事实 → 资格校验 → 方案审核 → 执行结果”调用链，并解释一次失败恢复。
这个项目能够提供求职证据，不能代替对源码和业务约束的实际理解。
